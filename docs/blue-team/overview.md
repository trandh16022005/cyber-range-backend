# Blue Team Overview

## 1. Introduction

### 1.1. Purpose

This document defines the overall business requirements, responsibilities, operational workflow, and system interactions of the Blue Team in the Cyber Range platform.

It establishes a common understanding of how Blue Team participants perform defensive activities during an exercise and how the platform supports, monitors, and evaluates those activities.

### 1.2. Background

The Cyber Range platform provides a controlled cybersecurity training environment where participants can practice defending systems against simulated cyber attacks.

Within an exercise, the Blue Team is responsible for monitoring security-related information, identifying suspicious activities, detecting attacks, identifying compromised assets, responding to incidents, and restoring affected services.

The platform collects relevant events and operational evidence to support the automatic assessment of defensive activities.

### 1.3. Document Scope

This document covers:

- Blue Team objectives and responsibilities.
- Blue Team operational scope.
- Relationship between Blue Team and other system roles.
- Overall defensive workflow.
- Interaction with Cyber Range components.
- Functional scope and limitations of the first version.

Detailed detection procedures, incident response operations, and assessment conditions are defined in separate documents.

### 1.4. Terminology

| Term | Description |
|---|---|
| Cyber Range | A controlled environment for cybersecurity training and exercises. |
| Exercise | A training session containing a scenario, participants, assets, and defensive tasks. |
| Blue Team | Participants responsible for defensive activities during an exercise. |
| Red Team | Participants or simulation components responsible for generating attack activities. |
| White Team | Participants responsible for supervising and managing an exercise. |
| Asset | A system component or machine participating in an exercise. |
| Event | A recorded occurrence generated by a system or monitoring component. |
| Evidence | Information used to verify an action, event, or assessment result. |
| Incident | A security-related situation requiring investigation or response. |
| Assessment | The process of evaluating whether a defensive task satisfies its requirements. |

## 2. Blue Team Overview

### 2.1. Definition

The Blue Team is the defensive team within a Cyber Range exercise.

Its primary responsibility is to protect the systems and services within the exercise environment by identifying suspicious activities, investigating security events, responding to incidents, and restoring affected services.

The Blue Team performs defensive tasks based on the objectives and requirements defined by the exercise scenario.

### 2.2. Objectives

The main objectives of the Blue Team are:

1. Monitor security-related events generated by exercise assets.
2. Identify suspicious activities and potential attacks.
3. Detect attack scenarios defined by the exercise.
4. Identify assets affected by security incidents.
5. Perform appropriate incident response actions.
6. Restore affected services to an operational state.
7. Submit incident reports containing relevant findings and evidence.

### 2.3. Responsibilities

| Responsibility | Description |
|---|---|
| Monitoring | Observe events and operational information collected from exercise assets. |
| Detection | Identify activities that match defined attack indicators or detection conditions. |
| Investigation | Analyze available events to understand the nature and scope of an incident. |
| Asset identification | Determine which asset is affected by an incident. |
| Isolation | Perform authorized actions to isolate an affected asset. |
| Recovery | Restore affected services and verify their operational status. |
| Reporting | Record incident information, response actions, and findings. |

### 2.4. Role in Cyber Range

The Blue Team operates within an exercise environment prepared and controlled by the platform.

The platform provides the environment and collects relevant information. The Blue Team performs defensive activities. The Assessment Engine evaluates the activities based on predefined conditions.

The Blue Team is therefore both an operational participant and the subject of defensive skill assessment.

## 3. Blue Team Operational Scope

The first version of the platform focuses on seven defensive tasks.

### 3.1. Log Analysis

The Blue Team observes and analyzes security-related logs and events collected from exercise assets.

Relevant information may include:

- Authentication events.
- SSH authentication events.
- Web server access events.
- System events.
- Network security events.
- Asset and service status changes.

Log collection is performed by the platform or its collection components. Blue Team participants use the collected information to investigate and detect suspicious activities.

### 3.2. Attack Detection

The Blue Team identifies attack activities based on available events and predefined detection requirements.

The first version focuses on:

- Port scanning detection.
- SSH brute-force detection.
- Web attack detection.

Detection requires sufficient evidence to support the conclusion. Merely receiving or viewing a log does not mean that an attack has been detected.

### 3.3. Compromised Host Identification

When an attack is detected, the Blue Team identifies the asset affected by the incident.

The identification result should reference an asset belonging to the current exercise.

### 3.4. Host Isolation

The Blue Team performs an authorized isolation action against an affected asset.

The platform records the action and verifies the resulting asset state where supported.

### 3.5. Service Recovery

After the incident has been handled, the Blue Team restores the affected service.

The recovery result must be verified using the service or asset status rather than relying exclusively on a participant's statement.

### 3.6. Incident Reporting

The Blue Team submits an incident report containing relevant information about the detected incident and response process.

The report should provide enough information for the instructor and Assessment Engine to review the defensive activity.

## 4. Blue Team Roles and Permissions

### 4.1. Blue Team Participant

A Blue Team participant is a user assigned to the Blue Team role in a specific exercise.

The participant can perform defensive tasks according to the exercise configuration and the permissions granted by the platform.

### 4.2. Relationship with System Roles

The platform distinguishes between system-level roles and exercise-level roles.

System roles include:

- `ADMIN`
- `INSTRUCTOR`
- `STUDENT`

Exercise roles include:

- `RED`
- `BLUE`
- `WHITE`

The Blue Team role is an exercise-level role. It does not replace or modify the user's system-level role.

A user must satisfy both system-level authorization and exercise participation requirements before performing an operation.

### 4.3. Relationship with White Team

The White Team supervises and manages the exercise.

The White Team is responsible for exercise-level operations and supervision according to the platform's authorization rules.

Blue Team participants perform defensive tasks and should not have permission to modify exercise lifecycle operations unless explicitly authorized by the platform.

### 4.4. Exercise Participation

Blue Team participants can access information and functions associated with exercises to which they are assigned.

The platform must enforce exercise-level data isolation so that participants cannot access unrelated exercise data.

## 5. Blue Team Operational Workflow

### 5.1. Preparation

Before performing defensive tasks, the Blue Team receives access to the assigned exercise.

The exercise environment contains the assets, services, scenario, and task requirements configured for that exercise.

### 5.2. Monitoring and Analysis

The Blue Team observes available security events and system information.

Participants analyze collected information to identify suspicious activities.

### 5.3. Detection

When available evidence satisfies a detection condition, the Blue Team records or confirms the corresponding detection result through the platform.

The detection result should be associated with the relevant exercise and attack scenario.

### 5.4. Incident Response

After identifying an incident, the Blue Team investigates the affected asset and performs appropriate response actions.

For the first version, the main response activities are host isolation and service recovery.

### 5.5. Recovery

The Blue Team restores the affected service and verifies that the service is operational.

The platform records the resulting state for assessment.

### 5.6. Reporting

The Blue Team submits an incident report describing the incident, affected assets, detection findings, response actions, and recovery result.

The report becomes part of the evidence used for assessment.

---

## 6. Interaction with Other System Components

### 6.1. Red Team

The Red Team generates attack activities according to the exercise scenario.

These activities produce events that may be collected and analyzed by the platform.

The Blue Team uses the available information to detect and respond to the activities.

### 6.2. Cyber Range

The Cyber Range provides the controlled environment in which exercise assets and services operate.

It is responsible for providing the environment required by the exercise scenario.

### 6.3. Event Collection

The event collection component gathers information from supported sources, such as authentication logs, web server logs, system events, and asset status changes.

Collected information is made available to other platform components for processing and assessment.

### 6.4. Evidence Management

Evidence Management stores or references information used to verify defensive activities.

Evidence may include:

- Relevant security events.
- Detection records.
- Asset status changes.
- Service status changes.
- Isolation results.
- Recovery verification results.
- Incident reports.

### 6.5. Assessment Engine

The Assessment Engine evaluates whether the Blue Team has completed each defensive task.

It uses predefined assessment conditions and available evidence.

### 6.6. Scoring Engine

The Scoring Engine calculates scores based on assessment results and the scoring criteria defined for the exercise.

The Blue Team does not directly determine or submit its own final score.

### 6.7. Web Platform

The Web Platform provides interfaces for participants and instructors to access exercise information, review events, perform supported defensive actions, submit reports, and view assessment results.

---

## 7. Blue Team Data Flow

The overall data flow is:

1. The exercise environment generates system and security events.
2. The Event Collection component collects relevant information.
3. The platform processes and stores collected events.
4. The Blue Team analyzes available information.
5. The Blue Team performs detection and incident response activities.
6. The platform records defensive actions and resulting system states.
7. Evidence Management stores or references relevant evidence.
8. The Assessment Engine evaluates defensive tasks.
9. The Scoring Engine calculates the exercise score.
10. The Web Platform displays assessment results.

Conceptual flow:

```text
Red Team / Attack Simulation

            v

            v

      |            |
      +-----+------+
            |
            v
       Evidence
            |
            v
    Assessment Engine
            |
            v
      Scoring Engine
            |
            v
       Web Platform
```

## 8. V1 Functional Scope

The first version focuses on the following capabilities:

| Category | V1 Capability |
|---|---|
| Event monitoring | View collected security and system events. |
| Attack detection | Detect port scanning, SSH brute force, and web attacks. |
| Asset identification | Identify the asset affected by an incident. |
| Host isolation | Perform and verify supported isolation actions. |
| Service recovery | Restore and verify supported services. |
| Incident reporting | Submit incident reports. |
| Assessment | Evaluate the seven predefined defensive tasks. |
| Scoring | Calculate scores using the configured assessment criteria. |

The first version prioritizes a small number of clearly defined scenarios and verifiable defensive activities.

---

## 9. Limitations and Assumptions

1. Detection capabilities depend on the availability and quality of collected events.
2. The platform can only verify actions for which it has sufficient system information or evidence.
3. Isolation and recovery operations depend on the capabilities of the exercise environment.
4. Different asset types may provide different levels of operational information.
5. The first version does not aim to implement a complete enterprise-grade SIEM or SOAR platform.
6. The first version focuses on predefined scenarios rather than unrestricted attack detection.
7. Assessment results depend on the configured task conditions and available evidence.

---

## 10. Future Extensions

Potential future extensions include:

- Additional attack detection scenarios.
- Advanced event correlation.
- Threat hunting capabilities.
- More detailed forensic analysis.
- Extended Windows and Active Directory monitoring.
- Additional response actions.
- More complex incident workflows.
- Advanced assessment metrics.

These extensions are outside the required V1 scope unless explicitly added to the project requirements.
